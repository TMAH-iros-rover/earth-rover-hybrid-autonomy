방향 타당
보완 필수

SAM-TP 모델을 다시 튜닝하기 전에 통신·프레임·계획·명령·차체 반응을 분리해 측정하는 접근은 타당합니다. 다만 원래 플랜에는 동일한 frame, plan, command, telemetry를 연결하는 관측 계약과 대시보드 구현이 선행 단계로 명확히 포함되지 않았습니다. 이 문서는 두 작업을 1, 2단계로 승격한 보완본입니다.

구현 전 확인된 격차

Path는 합성 영상에만 존재

선택 경로는 보이지만 안전 후보, hard-reject 후보, 실제 footprint와 거절 사유를 동시에 비교할 수 없습니다.

제어값의 의미가 섞여 있음

대시보드는 controller 내부 linear/angular만 축약 표시하며 sign-flip 이후 SDK 요청값을 명확히 구분하지 않습니다.

HTTP 성공과 차량 반응을 구분하지 못함

command_transmitted=true는 요청 성공이지 바퀴가 실제로 움직였다는 증거가 아닙니다.

인과관계 ID가 없음

어떤 frame에서 생성된 plan이 어떤 command를 만들었고 어떤 RPM·heading 반응으로 이어졌는지 한 줄로 연결되지 않습니다.

보완된 실행 단계

각 단계의 검증을 통과하기 전에는 다음 단계의 실차 속도나 planner threshold를 조정하지 않습니다.

통합 관측 계약 구현

frame_id, plan_id, command_id를 도입하고 단일 JSONL 타임라인을 만듭니다.

  • 프레임 취득, 추론, 계획, 명령 요청·완료, telemetry 수신 시각 기록
  • clock source와 age 계산 기준 명시
  • 명령과 최초 RPM·heading 반응 자동 상관 분석

Live enable 조건

대시보드가 frame/plan/command age를 정상 표시하고, E-stop이 모든 상태보다 우선하며, actuator 무반응 시 zero command로 전환되는 dry-run 테스트가 통과해야 합니다.

각 시험은 사람이 즉시 정지할 수 있는 상태에서 수행하며 한 단계가 반복 성공하기 전에는 장애물 난이도나 속도를 높이지 않습니다.

예상 구현 산출물

  • 공통 timeline event schema와 JSONL recorder
  • Controller status의 frame/plan/command 상관 필드
  • SDK control request timestamp 및 response correlation
  • Candidate/footprint 좌표를 포함한 planner dashboard payload
  • Mission dashboard path canvas, control panel, trend graph, stale/no-response 경고
  • Replay fixture와 dashboard/controller 자동 테스트
  • Actuator characterization 결과 및 검증된 live config
이 문서는 구현 진행에 따라 각 단계 상태와 실측 결과를 갱신하는 기준 문서입니다.
